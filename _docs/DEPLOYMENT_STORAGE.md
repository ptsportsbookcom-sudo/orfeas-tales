# Deployment storage controls

The website publishes `site-dist/`, generated by `node scripts/build-site.js` after the existing smoke checks. Original images, recordings, alternate versions and release notes remain in source control unchanged. The build does not transcode media or change the website's paths, query strings, JavaScript, CSS or HTML.

The builder walks the final character, narration, story text and panel data, then includes literal HTML/JavaScript media dependencies and CSS URLs. It preserves fetched story text and background music. Missing dependencies and unsafe paths fail the build. Files are copied byte for byte and checked with SHA-256. Use a fresh checkout for each build; an existing output directory is deliberately rejected rather than removed.

Both GitHub CI and Vercel build the filtered output. `scripts/site-budget.json` caps output at 1.45 GB: current output is approximately 1.294 GB, leaving headroom for new episodes. Review the size report before increasing this budget. When adding new mechanisms for dynamically constructing paths, extend dependency discovery and regression tests before publishing.

Source-only files are no longer available at public URLs. This includes alternate recordings, source PNGs that the website does not use, and internal notes. The originals remain in Git. The separate TTS authoring helper stays available at its existing URL.

## Deployment history

Verified project retention on November 7, 2026: canceled, errored and pre-production deployments one day; production one week. Do not assume those intervals impose a strict count cap. Vercel has retention exceptions, including recent deployments, production aliases and active-branch previews, and deletion/re-evaluation can be delayed.

After a release is verified, close its PR and avoid leaving active unused preview branches. Review retained deployments when storage approaches the account allowance; preserve the current production deployment and selected rollback releases. Never delete original media to clear deployment history. Do not change another project's settings.

Before a production release: require smoke checks, build regression tests, a successful filtered build, and a preview check of all story/language asset mappings. Check Deployment Storage separately from transfer usage. A successful deployment or a low transfer figure does not establish storage capacity.
